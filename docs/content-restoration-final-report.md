## Original Content Source

The original EnglishApp content was stored in a SQLite database (`data.db`) committed at
the earliest git commit (`98321ac` — "hehe"). This database contained:

| Table | Records | Notes |
|-------|---------|-------|
| `users` | 1 | User "Phat" (id=1, target_exam=IELTS, target_score=9.0) |
| `vocabulary_cards` | 50,017 | 4,972 fully curated; 42,152 auto-generated placeholders |
| `user_vocab_progress` | 83 | 81 with user_id=1; SRS state (interval, easiness, repetitions) |
| `study_sessions` | 44 | 34 with user_id=1 |
| `study_plans` | 0 | Empty |
| `error_journal` | 0 | Empty |
| `content_cache` | 2 | Reading content cache entries |

**Key finding**: The original SQLite database had 50,017 vocabulary cards, but only ~4,972
had fully curated content (real English + Vietnamese meanings). The remaining ~42,152 were
auto-generated by `data/seed/__init__.py` using `wordfreq` word lists with placeholder text
("Common English vocabulary word: X" / "Từ vựng tiếng Anh thông dụng.").

The curated vocabulary was enriched during web migration via `data/seed/expand_vocab.py`
(Free Dictionary API, Datamuse API, Google Translate) and stored as:
- `data/seed/vocab.json` (5,000 words)
- `data/seed/vocab_enriched.json` (5,000 words, array synonyms/antonyms)
- `data/seed/vocab_fixed.json` (~100 manual corrections)
- `web/public/data/vocab.json` (5,251 words — enriched + fixed, frontend fallback)

The current web vocabulary (5,251 words) is the **correct production content**. It is an
enriched and corrected superset of the original curated vocabulary:

- All 5,251 entries have real English meanings, Vietnamese translations, phonetics, examples
- 5,213 entries have synonyms (up to 5 per word)
- 4,960 entries have antonyms (up to 5 per word)

- 0 placeholder/demo entries

The original SQLite's 50,017 entries were mostly low-quality auto-generated fillers that
should NOT be restored. The 5,251 curated entries represent the real vocabulary content.

## Manual Actions Required

1. **Apply Supabase seed SQL**: Run `supabase/seeds/seed_vocab_cards.sql` against the
   production Supabase database to sync vocabulary (5,251 words with `ON CONFLICT DO UPDATE`).

2. **Migrate user data**: After the user creates a Supabase auth account, replace
   `:target_user_id` in `supabase/seeds/migrate_user_data.sql` with the actual user UUID,
   then run the SQL to restore SRS state and study sessions.

3. **Expand question bank** (optional): The question bank has only 6 questions (demo-level).
   Consider expanding it with more grammar questions across all CEFR levels.

4. **Start the Render API** (optional): The production API at `englishapp-api.onrender.com`
   is not running. Starting it would enable server-side SRS, study session persistence, and
   user authentication. The frontend works without it via seed data fallback.
